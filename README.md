# Лендинг «Личная CRM»

Одна статичная страница: рассказывает о личной CRM и ведёт в приложение.
Сделана по макету из `design/` на Astro и Tailwind CSS 4.

## Как запустить у себя

Нужны Node.js 22+ и pnpm.

```sh
pnpm install
pnpm dev       # страница с автообновлением: http://localhost:4321
pnpm build     # готовая статика в папке dist/
pnpm preview   # посмотреть собранную версию из dist/
```

## Куда ведут кнопки

Все кнопки («Открыть», «Открыть приложение», «Добавить первый контакт») ведут на адрес
из переменной `PUBLIC_APP_URL`. По умолчанию это `https://app.stayintouch.site`
(задан в `astro.config.mjs`). Чтобы поменять адрес, добавьте строку в `.env`:

```
PUBLIC_APP_URL=https://app.example.com
```

## Где что лежит

- `src/styles/tokens.css` — дизайн-токены: цвета, шрифты, размеры текста, отступы, скругления
- `src/styles/global.css` — общие стили, маски фото, появление блоков при прокрутке
- `src/components/` — секции страницы: `Hero`, `Problem`, `Solution`, `Benefits`, `FinalCta`,
  а также шапка, футер, кнопка и карточка контакта
- `src/scripts/reveal.ts` — появление блоков и размытие фото при прокрутке
- `src/assets/` — фотографии; при сборке Astro сжимает их в AVIF/WebP
- `design/` — макет и исходные тексты (в сборку не попадает)

## Как выкатить на сервер

Лендинг на сервере: https://stayintouch.site

### Выкатить новую версию

Отправьте изменения в ветку `main`:

```
git push
```

Дальше всё произойдёт само, обычно за 1–2 минуты. Следить за выкаткой: на GitHub вкладка **Actions** → **Deploy**. Зелёная галочка — новая версия на сервере.

Проверить руками: откройте https://stayintouch.site/version.txt — там номер (SHA) последнего коммита. Его видно на GitHub рядом с коммитом или командой `git log -1 --format=%H`.

### Что происходит при выкатке

1. GitHub собирает страницу (`pnpm build`) в папку `dist/` и кладёт в неё `version.txt` с номером коммита. На сервере ничего не собирается.
2. GitHub заходит на сервер под пользователем `landing` и через `rsync --delete` делает папку `/var/www/stayintouch.site` точной копией `dist/`: новые файлы подменяются разом в конце, лишние старые удаляются. Ключ этого пользователя умеет только загружать файлы в эту папку — ни команд, ни доступа к остальному серверу.
3. nginx сразу отдаёт новую папку.
4. GitHub проверяет снаружи: главная https://stayintouch.site отвечает 200, страница совпадает с только что собранной, а в `version.txt` — номер нового коммита.

### Если выкатка упала

На вкладке **Actions** будет красный крестик, GitHub пришлёт письмо. Отката нет: откройте упавший шаг, посмотрите ошибку, исправьте и отправьте новую версию.

- упала сборка (`pnpm build`) — на сервер ничего не попало, там работает прежняя версия;
- упала последняя проверка (Smoke test) — новые файлы уже на сервере, но сайт отвечает не так, как надо.

### Что где

| Что | Где |
|---|---|
| Как устроена выкатка | `.github/workflows/deploy.yml`, скрипты в `deploy/` |
| Файлы сайта на сервере | `/var/www/stayintouch.site`, владелец — пользователь `landing` |
| Настройка nginx для лендинга | блок `stayintouch.site` в `/etc/nginx/sites-available/stayintouch` |
| Настройки в GitHub | Settings → Secrets and variables → Actions: секрет `DEPLOY_SSH_KEY` (ключ для входа на сервер), переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` (отпечаток сервера), `SITE_URL` |

Первичная настройка сервера под выкатку — `deploy/bootstrap.sh`. Она уже сделана, повторять не нужно. Не запускайте заново общую настройку сервера `~/server-setup.sh`: она вернёт папку сайта пользователю `crmapp`, и выкатки начнут падать.
